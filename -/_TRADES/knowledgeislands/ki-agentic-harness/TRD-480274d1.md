# TRD-480274d1: Default cross-repository authority

## Context

An agent operating in one KI repository needs a clear authority boundary when sibling repositories are locally visible. `tools-ki` has adopted a temporary local rule: work in the selected repository may be read, written, and committed within task scope; other repositories are read-only by default, require explicit chat approval for writes, and require separate explicit approval for each commit. An outbound trade does not itself grant authority to modify the receiver.

## Submission

Make this a portable `ki-repo` default for KI repositories. `ki-repo` should define selected-repository authority, default read-only treatment of sibling repositories, explicit approval for cross-repository writes, and separate approval for a cross-repository commit after its target and scope are clear. `ki-git` should continue to govern how an already-authorised commit is prepared, staged, and described, not whether a repository may be changed.

## Constraints

Do not prevent a user from explicitly broadening authority for a bounded task, and do not turn a locally readable sibling checkout into an implicit write target. Preserve the receiver-only authority of inbound trades and the sender-only authority of outbound trades. The Harness retains all decisions on wording, enforcement, agent-instruction projection, and how existing repository-local temporary rules are retired once the shared default exists.
